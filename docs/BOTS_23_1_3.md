# Player-level bot difficulty (23.1.3)

The 23.1.3 client already contains several complete bot configurations. This
backend selects among those stock tiers per authenticated player instead of
inventing new aim, damage or weapon values.

## Confirmed client contracts

Read-only inspection of the exact client and the connected device established
three active configuration paths:

- `Bots` (`ConfigId 52`) contains four legacy `AILevelSettings` entries.
- `MatchmakingBots` (`ConfigId 86`) contains six equipment tiers and four AI
  settings tiers.
- `MMBots` (`ConfigId 147`) contains the current named presets (`Easy`,
  `Middle`, `Hard`, `VeryHard`), equipment loadouts and AI tiers.

The stock regular-bot controller accepts only AI indices 0–3. Player level 65
must therefore never be passed as the AI index. The frozen matchmaking flow
also has a fallback equipment id of `1`, which is the starter loadout, and the
observed match did not call the normal AI-level setter. That combination
explains level-65 matches whose bots still use default weapons.

## Backend policy

At each authenticated config poll, the backend maps the current profile level
to one of the client's stock bands:

| Player level | Stock preset | Legacy AI tier |
| --- | --- | --- |
| 1–10 | Easy | 0 |
| 11–25 | Middle | 1 |
| 26–45 | Hard | 2 |
| 46–65 | VeryHard | 3 |

For all three config paths, every fallback slot is materialized from the
selected stock tier. `MMBots.dl` is changed from starter loadout `1` to the
strongest equipment loadout in the selected preset. At level 65 this is the
stock VeryHard loadout range 33–47, with default AI tier 3 and allowed tiers
2–4. This makes the behavior deterministic even when the retired matchmaking
transaction omits the equipment or AI-level assignment.

At exactly level 65, the backend also adds three stock client weapons requested
for the maximum-rank rotation: Ultimatum (`834001`, primary), Vertical Grip
Device (`1175001`, special), and Big Buddy (`94001`, heavy). Legacy fallback
sets contain all three. Matchmaking weapon sets distribute them through the
rotation, while the final/default set contains all three so the fallback path
can select them as well. Levels 1–64 keep their prior stock loadouts unchanged.

The generated document is fingerprinted after scaling, so a level-band change
invalidates the previous cached copy. `Bots` and `MatchmakingBots` use the
client's measured inline-JSON path; `MMBots` keeps its measured binary config
attachment path.

## Ownership and limitations

Photon's room master owns and simulates regular bots. Consequently, the room
master's authenticated profile level selects the effective room difficulty. A
level-65 player who joins a room mastered by a lower-level player can still see
that master's lower band. The backend does not rewrite combat packets, add
cheat-like accuracy, or modify the Android client.

The config is consumed during login/config initialization. Restart the game
before judging a newly deployed band. Static parsing and device model
inspection prove delivery; an actual completed match is still required to judge
feel, weapon selection and balance.

## Live verification

On the connected level-65 profile, the rebuilt backend passed the scaled bot
configs without changing progress or clearing application data. During the
first real battle after deployment, the user confirmed that bots were carrying
different, stronger weapons instead of the default set. This verifies the
reported defect at the gameplay surface. Aim feel, kill rate and every game
mode were not exhaustively benchmarked.
