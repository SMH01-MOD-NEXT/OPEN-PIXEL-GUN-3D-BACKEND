# 23.1.3 loading recovery — 2026-10-19

## Confirmed failure

The client stopped at 76% while the native bootstrap, Photon AppID envelope,
and remote-config HTTP requests succeeded. No Socket.IO connection was made.
Passive coordinator tracing showed a repeated stock HTTP authorization/retry
cycle. That HTTPRequest still targeted the vendor's
`server-v2.pixelgun3dserver.com/auth_v2/`: BestHTTP does not use the hooked
UnityWebRequest/WWW methods. A previous successful September log likewise had
no local HTTP auth request before socket setup; authorization was not fully
self-hosted. The exact upstream change/date is not established.

An independent launch problem was also found: a backend started without `.env`
returned AppID 503. The recovery process runs with the existing `.env`; no new
keys, credentials or security bypasses were introduced.

## Fix

The matching frontend redirects BestHTTP.HTTPRequest.Send through the same
retired-host rewrite used for Unity requests. The backend accepts the actual
23.1.3 binary auth packet and responds in that format, not JSON. The stock
client then initializes WebSocketManager and uses the existing config/progress
protocol. No forced authorization state or loading-percentage patch is used.

Wire contract, verified against 23.1.3 ARM64:

- Request encoder RVA `0x3C13F94`; response decoder `0x3C1554C`.
- Each field is `[int16 key-byte-length][int16 value-byte-length]`, followed by
  UTF-16LE key and value with a per-code-unit shift.
- The last value length includes a two-byte trailer; the trailer's low byte is
  the shift. This is reversible obfuscation, **not encryption**.
- The callback `0x3C1483C` reads `player_id`, `hash`, `create_to`, `url`,
  `mm_url`, `token`, `wait`. Success omits `err_code` entirely.
- `url` uses the origin the device reached and `/socket.io/`; bootstrap query
  credentials are URL-encoded. The existing session is authenticated/reused,
  not rotated or replaced by a duplicate managed-client registration.
- Lengths, packet size, duplicate keys and incomplete trailers are checked.
- Auth response bodies are excluded from trace capture. Frontend URL
  diagnostics mask queries/fragments because socket URLs contain credentials.
- Existing GET/JSON legacy callers remain supported.

## Running process

Recovery uses transient user unit `opg3d-backend-recovery.service` with
Restart=on-failure, the project working directory, and `.env` sourced before
executing `bin/opg3d-backend`. It is **not** a persistent boot-time installation.

```sh
systemctl --user status opg3d-backend-recovery.service
systemctl --user restart opg3d-backend-recovery.service
```

Do not launch an additional copy on port 8080. A transient unit disappears
when the user manager is restarted; regular launches must also load `.env`.
Existing unrelated administrator/relogin changes were preserved and are not
part of the recovery commit.
